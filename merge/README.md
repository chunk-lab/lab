# かまってチャンクタウン！ 港のマージ工房

町人1人につき2品を用意して贈る、スマホ縦持ちの港の工房。はなの最初の注文はドーナツとコーヒー。クッキー同士をドラッグで重ねてカップケーキにし、カップケーキ同士を重ねてドーナツを作る。2品そろった町人を押すとそのまま届ける。

## 起動

`merge/index.html`を開く。外部ライブラリ・フォント配信・ビルド・ネット接続は不要。HTTPでの通常プレイはフォルダ内のJSONを読み、PCで展開して直接開いた場合はHTML内の同じデータを使う。スマホではプレビューURLから起動する。保存先はブラウザ・オリジンごとに独立する。

確認先一覧は https://chunk-lab.github.io/lab-preview/ 。対象ブランチは`merge-game`。本体、町への入口、公開設定、リリースはClaudeが担当する。

## 遊び方

- 同じ種類・ランクの品物をふたつ重ねると次の品物になる。縞模様のマスに同じ品物を重ねるとロックが解ける。
- 違う品物をドラッグで重ねると位置が入れ替わる。生成機もドラッグで移動・交換できる。ロック品の上は、対応する同じ品物による解放だけができる。
- 生成機の盤面アイコンには、出てくる2系列の初級素材を小さく表示する。品物の左下には対応する生成機の色を付け、選択欄には生成元の名前を表示する。注文カードは2品揃ったもの、1品揃ったもの、必要品への近さの順で自動的に並ぶ。
- 生成機をタップするとエネルギーを1消費する。合体と移動は無料。連続生成後は休止し、時間が来ると再開できる。
- 最初は3人が注文を出す。2・4・6・9・12件のお届けで席が1つずつ増え、同時に出る町人は最大8人。画面上部を横にスワイプして各注文を見られる。1人につき異なる2品を吹き出しに表示し、持っている品だけにチェックが付く。
- 盤面と収納の在庫を合わせて2品をそろえる。ロック品は対象外。両方そろった注文カードを押すと確認画面なしで一括して渡す。町人は退場し、後ろの町人が左に詰めて、空席に別の町人が自動で来る。好感度と次の注文は保存され、再来店時に引き継ぐ。片方だけでは何も消費しない。
- 注文を追跡するとチャンク君が不足品に合わせ、今できる合体か対応する生成機を案内する。お届け後は一定確率で部品が出る。部品と生成機も同種・同ランク同士をドラッグで合体して育てる。
- 町人を招くと選んだ席の町人と交代する。席を離れた町人の注文と好感度は保持される。チャンク君を除く13人が対象。旧版の注文は、盤面・保存値を引き継ぎつつ2品に移行する。
- 13人全員へのお届けで1ターン完了。「13人全員に渡せた」と表示し、チャンク君が登場→プレゼント配布→退場。次ターンの町人の注文に関連する初級素材を最大10個、空きマスに配る。空きが少なければ入る分だけ配る。各お届けでは好感度・経験値が増え、生成機の部品は一定確率で得る。
- 生成機はカフェ、工具箱、海の宝箱、裁縫箱の4種。各2ラインで、カフェはLv.1〜9、ほかはLv.1〜8。通常マージで作れるのは全ラインLv.8までの64品。カフェLv.9の2品は特別合成の材料・個数が未決定なので図鑑に予告表示し、作成・注文の対象にしない。発見品は図鑑に記録する。
- 選んだアイテムは収納・売却できる。売却前に金額を示し、確定時に共通コインを加算する。生成機は盤面に残る。
- 町人は13人。チャンク君は案内とヒント担当。追跡中の注文を基準に、渡す・合体する・生成する手順を案内する。
- 上のコインでお届け記録、エネルギーで回復情報を開く。「？」の遊び方画面から効果音を切り替えられる。初期値はオン。生成物は生成機の中心から画面上を放物線状に跳ねて着地し、その時点で盤上の品物が現れる。生成・合体・お届けに短い音と動きが付く。

### 辞書データへの差し替え

問題は配列で、1問の例は次のとおり。辞書や問題バンクからこの形式へ変換すれば、画面や判定の変更は不要。`answer`は正解の選択肢の0始まりの番号。文字列はテキストとして描画する。

```json
{"prompt":"「コーヒー」は英語で？","options":["coffee","cookie","cocoa"],"answer":0}
```

単独版では正解するとモックの今日の解答数を1増やす。現在は1問あたり1エネルギーで、学習による回復回数に制限はない（エネルギーの所持上限はある）。間違いは再挑戦できる。正解済みの問題でボタンを連打しても二重に加算しない。問題は一巡すると最初に戻る。本体bridgeがある場合は本体の学習実績を参照する。

## 本体へ取り付けるとき

本物の `window.MergeBridge` を**ゲームを開く側のwindow**に、`bridge.mock.js`より先に設定する。別ページやiframeを使う場合はそのページ内で初期化する。既にbridgeがあればモックは何も登録しない。以下はすべて `window.MergeBridge` 配下。同期値とPromiseに対応する。

| 対象 | 関数 | 使用方法 |
| --- | --- | --- |
| コイン | `coins.get()`, `coins.add(n, reason)`, `coins.spend(n, reason)` | 売却時に正数と `merge.sell` を渡す。不足時のspendはfalse |
| ダイヤ | `gems.get()`, `gems.add(n, reason)`, `gems.spend(n, reason)` | モックは対応。ゲーム内の消費・報酬は未設定 |
| 持ち物 | `items.add(id, n)`, `items.get()` | モックは対応。本体への持ち出し条件・ID対応を決めるまでは盤面と収納に保存 |
| 好感度 | `affection.get(npcId)`, `affection.add(npcId, n)` | 贈り物で加算。共通値を表示 |
| 学習 | `english.solvedToday()` | 今日の非負整数を読む。マージ側で回復量を計算 |

`get`・`solvedToday`は数値を返し、`items.get`は個数の辞書を返す。加算が完了して値を読める時点で`add`を完了させる。失敗は例外またはPromiseのrejectで伝える。`add`に負数は渡さない。ゲーム側から本体のlocalStorageや町のコードを読まない。

表示名とIDはデータで対応させる。哲学者レオは引き継ぎの `tetsu`、潮見さんは `suna` を採用。組み込み前に本体のIDと照合する。チャンク君は `chunkkun` で、通常注文の対象外。

## 保存・再開

マージ側は `cs:merge:practice:v2`（単独）または `cs:merge:live:v2`（本体）に `version: 2` を持つ状態を保存。v1のキーは変更せず残す。初回起動時、旧セーブがあれば進行回数・好感度の共通値・エネルギー・同名の品物・生成機をv2へ移す。採用しなかった品と旧注文はv2に持ち込まず、旧セーブは保管する。モックの財布・住人・解答数は `cs:merge:mock:` 配下。ブラウザの日付ごとに換算済み解答数を記録し、再読み込みと復帰時に差分だけ反映する。上限超過分は持ち越さない。

贈り物・売却では、盤面の結果、加算先、加算前の値、増分を先に一緒に記録する。再開時、加算前なら実行、加算済みの値なら完了として扱う。値がどちらにも一致しない場合は保存を残して停止する。これは町と同時に動かない前提の復旧策。同じ財布や好感度を他のクライアントが同時更新する場合、値の一致だけで取引を一意に識別することはできない。必要になれば取引IDによる重複防止をbridge側と相談する。Web Locks対応ブラウザでは同じモードを同時に2画面で操作できない。

## 調整と引き継ぎ

生成元・品物・13人完了の流れは2026年11月16日のv2仕様書に基づく。初期エネルギー・回復速度、生成回数・休止時間、部品獲得率、要求ランク、好感度・経験値、売却額は試遊用の仮設定。13人完了時の配布数は以前の要望に合わせて最大10個とした。カフェLv.9特別合成は材料とUIが未決定。街側と要求を共有する方法、持ち物の持ち出し、ダイヤの使い道、本体と日付切り替え時刻は組み込み時に調整する。
